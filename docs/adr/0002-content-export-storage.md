# ADR 0002：以 D1 保存推播內容對照

- 狀態：已採用
- 採納日期：2026-09-19
- 關聯：[ADR 0001](0001-fcm-topic-push-gateway.md) 的內容對照與 CSV 交付要求

## 背景與約束

[ADR 0001](0001-fcm-topic-push-gateway.md#csv-匯出與交付) 要求以 `push_id` 對應通知內容與原生成效，交付活動方自行保存。Gateway 因此必須獨立保存每筆公開推播的完整內容，直到交付完成，不能依賴執行日誌的保存期限。

資料是小型結構化紀錄，需要依活動與時間範圍查詢。部署不得要求綁定有效付款方式；此約束涵蓋 Gateway 執行、內容保存及既定的成效交付。

## 決策與理由

使用由 OPass 中央維運的 Cloudflare D1，透過 Worker binding 保存推播內容與已知派送結果。以活動 ID 與 `push_id` 識別紀錄，支援依活動及時間範圍匯出內容對照。

D1 可直接整合既有的 Worker 執行環境，並以 SQL 處理所需的範圍查詢，符合小型內容紀錄與活動 CSV 交付的需求，中央團隊無須自行維運資料庫伺服器。

D1 只供中央 Worker 與授權維運者存取，活動方取得限定自身活動的匯出資料。沿用 ADR 0001 的授權與活動隔離，不新增主辦方資料庫權限、內容查詢 API 或報表後台。

## 保存與失敗語意

- 在任何 FCM 派送前保存完整內容快照，包含由 key 決定的活動、中央主辦名稱、角色、雙語本文、URI、建立時間與固定期限。保存失敗即停止，不呼叫 FCM。
- 派送結束後保存已知結果，內容快照不隨結果更新。結果保存失敗仍回傳真實派送結果，並以不含憑證的日誌記錄已知結果與保存錯誤。
- D1 寫入與 FCM 派送之間沒有跨服務交易。缺少結果只表示紀錄不完整，不能推論全部未送出，也不能據此補送。
- 內容至少保存到 CSV 交付完成，再依活動約定清理。停發不觸發刪除；隔年保存由活動方負責。

## 取捨與重新評估條件

D1 成為派送前的必要依賴，保存失敗會降低推播可用性；接受這項取捨，以確保開始派送的操作都有內容可供交付。中央團隊仍須負責資料結構變更、存取權限、備份及清理。

部署前須驗證當時的服務條件與實際用量能同時滿足不綁付款方式、內容保留及既定成效交付。若供應商條件、資料規模或交付需求改變而無法滿足這些約束，須重新評估決策，不默認轉付費或刪除未交付內容。成效平台的具體方案不在本決策範圍。
